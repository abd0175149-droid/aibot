# ٨ — السقوف والقياس والفوترة

## ٨.١ العدّاد الأساسيّ: نافذة المحادثة

### الخوارزميّة الحرفيّة

```
عند كلّ رسالة واردة:
  w = النافذة المفتوحة لهذه المحادثة (closed_at IS NULL)
  إن لم توجد:
      أنشئ نافذة { opened_at: now, expires_at: now+24h, billed_at: null }
  وإلّا:
      w.expires_at = now + 24h            ← التمديد لا يفتح نافذةً جديدة
  w.messages_in++

عند أوّل رسالة صادرة داخل النافذة (بوت أو موظّف):
  إن كانت w.billed_at فارغة:
      تحقّق من السقف:
         المستهلَك = COUNT(windows WHERE billing_period = الشهر AND billed_at IS NOT NULL)
         إن تجاوز السقف ⟵ طبّق سياسة التجاوز (٨.٤)
      w.billed_at = now
      w.billing_period = YYYY-MM بتوقيت المستأجر
  w.messages_out++

مهمّة صيانةٍ كلّ ١٠ دقائق:
  أغلق كلّ نافذةٍ مضى expires_at عليها (closed_at = expires_at)
```

### الحالات الحدّيّة — محسومة سلفاً

| الحالة | القرار | لماذا |
|-------|--------|-------|
| نافذة تُفتح آخر الشهر وتمتدّ للتالي | تُفوتَر على **شهر فتحها** فقط | لا تُفوتَر نافذةٌ مرّتين، أبداً |
| رسالة وارد بلا أيّ ردّ | **لا تُفوتَر** | لا عملَ أُنجز، والعميل لا يدفع على المزعجين |
| الموظّف ردّ والبوت مطفأ | **تُفوتَر** | المنصّة قدّمت الخدمة (وهو خيارٌ في الباقة إن أردت غير ذلك) |
| الساحة (playground) | لا تُفوتَر كنافذة، وتُحتسب من التوكنز | ليست زبوناً |
| إشعارٌ آليّ (تأكيد حجز مثلاً) | يفتح نافذةً ويُفوتَر | استهلك موارد فعليّة |
| رسالةٌ فشل إرسالها | لا تُفوتَر؛ ويُلغى الختم إن كانت الأولى | لا فوترة على فشل |
| المحادثة نفسها تُغلق وتُفتح خلال الـ٢٤ | نافذةٌ واحدة | التعريف زمنيّ لا سلوكيّ |

### الشفافيّة

شاشة «الاستهلاك» عند العميل تعرض **جدول النوافذ نفسه**: الرقم، وقت الفتح، وقت الفوترة، عدد
الرسائل، والكلفة. قابلٌ للتصدير CSV. عدّادٌ لا يستطيع العميل مراجعته بنفسه = نزاعٌ في أوّل شهر.

## ٨.٢ العدّاد الثاني: التوكنز (قرار ق٢ — الافتراضيّ مفتاح المنصّة)

كلّ ردٍّ يكتب صفّاً في `ai_runs` بتوكنزه الفعليّة ونموذجه و`key_owner`. الكلفة = التوكنز ×
سعر النموذج من `prices` **لحظة العرض** (فتصحيح السعر يصحّح التاريخ كلّه).

- **مفتاح المنصّة** ⟵ الاستهلاك يُحتسب من سقف التوكنز في الباقة.
- **مفتاح العميل** (`ai_keys`) ⟵ يُعفى من سقف التوكنز، ويبقى سقف النوافذ. يُقاس الاستهلاك
  رغم ذلك (للعرض والتشخيص) ويُحسب كلفته عليه لا عليك.
- قاعدة تشغيليّة: **مفتاح المنصّة لا يُستعمل مطلقاً بعد تجاوز السقف**. هذا هو الفرق بين
  هامشٍ ومفاجأة.

### أين تذهب كلفتك فعلاً

من القياس الحقيقيّ: **98.8٪ إدخال**. أي أنّ كلفتك ≈ `حجم(الشخصيّة + المعرفة) × عدد النداءات`.
ثلاث روافع تخفضها:

1. **سقف حجم المعرفة في الباقة** (الرافعة الأقوى).
2. **ترتيب الموجّه للاستفادة من الكاش الضمنيّ** (`07.2`) — خصمٌ فوريّ بلا أثرٍ على الجودة.
3. **نموذجٌ أصغر للمهامّ السهلة**: تصنيفٌ سريع (تحيّة؟ سؤال متكرّر؟) قبل استدعاء النموذج
   الكامل. مؤجَّل للمرحلة السابعة — لا تُحسّن قبل أن تقيس.

## ٨.٣ شكل الباقات (أرقام ابتدائيّة — تُثبَّت بقرارك)

| البند | بداية | نموّ | أعمال |
|------|------|-----|-------|
| نوافذ شهريّاً | ٣٠٠ | ١٥٠٠ | ٥٠٠٠ |
| توكنز شهريّاً (مفتاح المنصّة) | ٥ م | ٢٥ م | ٨٠ م |
| حجم قاعدة المعرفة | ٢٠ ألف حرف | ٨٠ ألف | ٣٠٠ ألف |
| مستخدمو الفريق | ٢ | ٥ | ١٥ |
| أدوات HTTP مخصَّصة | ١ | ٥ | ٢٠ |
| الاحتفاظ بالمحادثات | ٦٠ يوماً | ١٨٠ | ٣٦٥ |
| الحملات والقوالب | ✗ | ✗ (بطلب) | بطلب + مراجعة |
| الدعم | بريد | بريد + واتساب | أولويّة |

**تحقّق من الهامش قبل تثبيت أيّ سعر:** باقة النموّ = ١٥٠٠ نافذة × ≈٤ ردود = ٦٠٠٠ ردّ ×
$0.0024 = **≈ $14.4 كلفة نموذجٍ شهريّاً** (مع معرفةٍ ٢٤ ألف توكن). إن كانت معرفة العميل
ضعف ذلك، فكلفتك ضعفان. **سعّر على حجم المعرفة لا على عدد الرسائل فقط.**

## ٨.٤ سياسة التجاوز (`overage_policy` في الباقة)

| السياسة | السلوك عند ١٠٠٪ | لمن |
|--------|------------------|-----|
| `handoff_only` (**الافتراضيّة**) | البوت يتوقّف؛ الرسائل تصل وتُوسَم «يحتاج تدخّلاً»؛ الموظّف يردّ يدويّاً بلا حدّ | الأسلم: لا زبونٌ يُترك بلا ردّ، ولا فاتورةٌ مفاجئة |
| `block` | البوت يرسل رسالةً واحدة مهذّبة ثمّ يصمت | للعملاء الحسّاسين للكلفة |
| `allow_bill` | يستمرّ ويُسجَّل التجاوز بسعرٍ للوحدة | للعملاء الكبار بموافقةٍ مسبقة |

التنبيهات: **٨٠٪** (تنبيه للعميل) · **٩٥٪** (تنبيه له ولك) · **١٠٠٪** (حادثة + إشعارٌ فوريّ
للطرفين + تطبيق السياسة). لا تنبيه يتكرّر لنفس العتبة في نفس الدورة.

## ٨.٥ الفوترة (الإصدار الأوّل يدويّ عمداً)

- دورةٌ شهريّة تبدأ بتاريخ التفعيل، بتوقيت المستأجر.
- عند انتهائها: توليد فاتورةٍ (PDF عربيّ) فيها النوافذ والتجاوز والتوكنز، وإشعارٌ للطرفين.
- الدفع خارج المنصّة (كليك/حوالة)، وأنت تضغط «مدفوعة» فتتجدّد الدورة.
- **مهلة سماح ٧ أيّام** ثمّ `status=suspended`: البوت يتوقّف، والبيانات تبقى، والإنبوكس للقراءة.
- الأرشفة بعد ٦٠ يوماً من التعليق: تصديرٌ كامل يُرسل للعميل ثمّ حذفٌ متتالٍ.
- بوّابة دفعٍ آليّة: بعد عشرة عملاء، لا قبل — الالتزام الضريبيّ والتقنيّ لا يستحقّ قبل ذلك.

## ٨.٦ لوحة الهامش (شاشتك الأهمّ)

لكلّ عميلٍ ولكلّ شهر: `الإيراد − كلفة النماذج = الهامش` ونسبته، مع ترتيب العملاء بالهامش
تصاعديّاً. الهدف: أن ترى عميلاً يستهلك أكثر ممّا يدفع **في شهره الأوّل** لا في السادس.
مؤشّرات مرافقة: كلفة الردّ الواحد لكلّ عميل، ومتوسّط الردود لكلّ نافذة، وحجم معرفته.
