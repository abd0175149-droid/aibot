## ١.٢ التدفّق الحيّ (من رسالة العميل إلى الردّ)

```
واتساب ← ميتا ← POST /api/whatsapp/webhook
   │  التحقّق من X-Hub-Signature-256 بـ WA_APP_SECRET   (routes:79)
   │  ردّ 200 فوراً ثمّ المعالجة لا متزامنة — ميتا تُعيد الإرسال وتعطّل الويبهوك إن تأخّرت
   ▼
processWebhookPayload                                    (inbox.service:343)
   ├─ field = phone_number_quality_update / account_update → صحّة الحساب
   ├─ field = message_template_status_update              → مرآة القوالب
   ├─ value.messages[]                                    → handleInboundMessage
   └─ value.statuses[]                                    → handleStatusUpdate (sent/delivered/read/failed)
   ▼
handleInboundMessage
   ├─ dedupe بالـ wamid (عمود unique)
   ├─ getOrCreateConversation(phone) — يوحّد الأردنيّ 07… والدوليّ E.164
   ├─ تخزين الرسالة + تحديث lastInboundAt  ← هذا ما يفتح نافذة الـ٢٤ ساعة
   ├─ كشف إلغاء الاشتراك بالنصّ أو بزرّ القالب
   └─ forwardToBot → handleBotIncoming(convId)
   ▼
handleBotIncoming                                        (bot.service:2819)
   └─ debounce 2000ms لكلّ محادثة + قفل processing + علم rerunAfter
   ▼
processConversation
   ├─ تحقّق: البوت مفعَّل عامّاً؟ المحادثة مفعَّلة؟ botPausedUntil مضى؟
   ├─ بناء السياق: history (آخر contextMessages) + بطاقة العميل + حقائق حيّة
   ├─ runAgent → Gemini بحلقة أدوات حتّى maxToolLoops
   ├─ حارس تسريب الأدوات: محاولة تصحيح واحدة + تنظيف إجباريّ
   ├─ sendMessage(source:'bot') — يمرّ بحارس النافذة مثل الجميع
   └─ recordBotUsage: توكنز، كلفة، أدوات، أعلام، زمن الردّ
```

## ١.٣ الجداول (في `schemas/admin.schema.ts`)

`wa_conversations` (محادثة لكلّ رقم: `botEnabled`، `botPausedUntil`، `lastInboundAt`،
`needsAttention`، `unreadCount`) · `wa_messages` (كلّ وارد وصادر، `wamid` فريد، حذف ناعم) ·
`wa_bot_settings` (**صفّ واحد** — الشخصيّة، المعرفة، النموذج، المفتاح، الأدوات، الأسعار) ·
`wa_bot_usage` (صفّ لكلّ ردّ: توكنز، نموذج، زمن، أدوات، أعلام) · `wa_customer_notes` ·
`wa_optouts` · `wa_templates` + `wa_campaigns` + `wa_campaign_recipients` (مرآةُ محرّك حملاتٍ
حُذف بعد الحادثة) · `wa_broadcasts` · `wa_message_templates`.

## ١.٤ الأدوات — ٤٠ أداة، كلّها مكتوبة بالكود

`get_available_activities` · `get_booking_cost` · `check_seat_availability` · `ask_confirmation` ·
`create_reservation` · `get_my_bookings` · `request_cancellation` · `save_customer_note` ·
`handoff_to_human` · `get_player_stats` · `request_password_reset` · `get_leaderboard` ·
`get_locations` · `send_location_link` · `send_social_links` · `request_account_link` ·
`confirm_account_link` · `send_quick_options` · `get_my_loyalty_card` · سبع أدوات للّعبة الحيّة ·
تسع أدوات إداريّة مقفلة بـ`ALWAYS_ADMIN_ONLY`.

**الملاحظة الحاسمة:** كلّ أداة = دالّة TypeScript + تعريف JSON + مفتاح في `DEFAULT_TOOLS_CONFIG`.
إضافة أداة لعميلٍ جديد = تعديل كود + بناء صورة + نشر. **هذا بالضبط ما يستحيل تكراره لعشرة عملاء.**
الحلّ في `07-bot-engine.md`: باني أدوات HTTP معرَّف بالبيانات.

## ١.٥ ما يستحقّ النقل حرفيّاً — منطقٌ دفعتَ ثمنه

1. **حارس النافذة في طبقة الإرسال** (`inbox.service` قرابة السطر 711) — ليس قاعدةً في دليل
   الموظّف بل شرطٌ في الكود، ولا مسار آخر إلى Cloud API في النظام. هذا وحده يمنع تكرار
   كارثة ٣١ تمّوز.
2. **حارس تسريب الأدوات** — النموذج يكتب اسم الأداة نصّاً للعميل. الحلّ المجرَّب: كشف +
   محاولة تصحيح واحدة (فقط إن لم تُنفَّذ أداة بعد، وإلّا ضاع التقرير) + تنظيف إجباريّ قبل الإرسال.
3. **دمج الرسائل المتتالية** — debounce ثانيتين + قفل + `rerunAfter`. العميل يكتب ثلاثة أسطر
   متتالية؛ بلا هذا يردّ البوت ثلاث مرّات ويتضارب.
4. **إيقاف البوت بعد ردّ بشريّ** — `source==='staff'` ⟵ `botPausedUntil = now + pauseMinutes`.
5. **نمط الزرّ للأفعال الخطرة** — الأداة تتحقّق وترسل أزراراً، والتنفيذ الفعليّ معالجٌ حتميّ
   يُعيد التحقّق من الصلاحيّة لحظة الضغط. النموذج يقترح ولا يُنفّذ.
6. **قياس الاستهلاك لكلّ ردّ** + سعرٌ لكلّ نموذج (`KNOWN_MODEL_PRICES` + خريطة في الإعدادات)،
   فتبديل النموذج لا يفسد حساب التاريخ.
7. **ترتيب الموجّه لاستغلال كاش المزوّد**: الثابت أوّلاً (الشخصيّة ثمّ المعرفة) والمتغيّر
   آخراً (الوقت، بطاقة العميل). عكسه يكسر البادئة المشتركة فتُفوتَر المعرفة كاملةً مع كلّ نداء.
8. **مراقب الصحّة** — يسأل Graph، يقفل الإرسال عند الرفض، **ويُنبّه عبر Push لا عبر واتساب**
   لأنّ تنبيه الواتساب يموت مع الحظر نفسه.
9. **توحيد الأرقام**: الأردنيّ `07XXXXXXXX` والدوليّ E.164، ولا تصادم لأنّ المحلّيّ يبدأ بصفر
   والدوليّ لا يبدأ به أبداً. (كانت الأرقام غير الأردنيّة تُسقَط بصمت قبل الإصلاح.)
10. **دورة حياة الإشعار**: إشعارٌ حيّ واحد لكلّ محادثة يُحدَّث ولا يتكرّر (upsert بالـtag)،
    ويُحذف عند فتح المحادثة من أيّ جهاز.

## ١.٦ ما يجب ألّا يُنقل — عيوبٌ بنيويّة

| العيب | أين | لماذا يقتل منصّةً متعدّدة العملاء | البديل |
|------|-----|-----------------------------------|--------|
| صفّ إعدادات واحد | `wa_bot_settings` | لا يمكن لعميلين أن يختلفا | إعدادات لكلّ مستأجر + نسخ منشورة |
| حالة في ذاكرة العمليّة | `debounceTimers` · `processing` · تعليق الإرسال · أقفال الربط | إعادة تشغيل واحدة = ردودٌ ضائعة وأقفال تتبخّر. مع عشرة عملاء يصير هذا يوميّاً | **BullMQ + Redis**: تأخير، قفل، إعادة محاولة، طابور موتى |
| مفتاح Gemini نصّ صريح في القاعدة | `wa_bot_settings.geminiApiKey` | نسخةٌ احتياطيّة مسرَّبة = مفاتيح كلّ عملائك | تشفير AES-256-GCM بمفتاح رئيس من البيئة |
| أدوات بالكود | `buildToolDeclarations` | كلّ عميلٍ نشرٌ جديد | باني أدوات HTTP بالبيانات |
| لا سجلّ لتغييرات الشخصيّة | تُحدَّث في مكانها | عميلٌ يفسد بوته ولا رجوع | نسخ (versions) + نشر وتراجع |
| توقيع الويبهوك اختياريّ | `if (env.WA_APP_SECRET)` | أيّ أحدٍ يحقن رسائل | إلزاميّ، وسرٌّ لكلّ مستأجر |
| لا حدّ معدّل لكلّ محادثة | — | حلقة رسائل أو مهاجم = فاتورة توكنز | حدّ لكلّ محادثة ولكلّ مستأجر بالدقيقة |
| رقم واحد في البيئة | `WA_PHONE_NUMBER_ID` | جوهر المشكلة | بيانات اعتماد لكلّ مستأجر في القاعدة |
| `create_reservation` لا تتحقّق بالكود من زرّ التأكيد | bot.service | قاعدةٌ في الموجّه = قاعدةٌ يمكن للنموذج كسرها | كلّ فعلٍ خطر خلف معالجٍ حتميّ |

## ١.٧ أرقام الإنتاج — أساس تسعيرك

- ٣١٦ محادثة · ١٢٠٧ ردّ بوت · ٦٤ ردّ موظّف · ٧٢ حجزاً مؤكّداً.
- منذ بدء القياس: ٣٨٥ ردّاً، **9.25M توكن إدخال**، **$0.94**، ≈ **$0.0024 للردّ**.
- **98.8% من الكلفة إدخال** — الموجّه + قاعدة المعرفة ≈ ٢٤ ألف توكن تُرسل مع كلّ نداء، والردّ
  الواحد قد يستهلك نداءين. ⟵ **الدرس التسعيريّ**: كلفتك تتبع **حجم قاعدة المعرفة** لا طول الردّ.
  عميلٌ بقاعدة معرفة ٥٠ ألف توكن يكلّفك ضِعفين. لذلك حجم المعرفة بندٌ في الباقة (`08`).
- الحادثة: ٢٥٠ قالباً تسويقيّاً في يومٍ واحد ⟵ **تعطيل الحساب في ٣١ تمّوز** بعد سبعة أيّام عمل.

## ١.٨ ماذا يعني هذا للمشروع الجديد

النقل الصحيح ليس `git clone` ثمّ `ALTER TABLE ADD tenant_id`. المشروع الحالي **تطبيقٌ لعميلٍ
واحد** مدموجٌ في منصّة ألعاب: أدواته تقرأ `activities` و`players` و`matches`، وبطاقة العميل
تبني رتبةً في موسم، والحقائق الحيّة تُحقن من نظام الولاء. فصل هذا أصعب من إعادة كتابته.

**الخطّة:** مشروعٌ جديد تُستورد إليه من الحالي: نصوص الحرّاس، صيغة حلقة الوكيل، شكل التعريفات،
منطق التوقيت والتطبيع، وأنماط الواجهة المجرَّبة. الخريطة الحرفيّة في `15-reuse-map.md`.
