# ٤ — المعمارية واختيار التقنيات

## ٤.١ المبدأ الحاكم

ثلاثة أشياء يستحيل إضافتها لاحقاً بلا إعادة بناء، فتُبنى في اليوم الأوّل:

1. **الطوابير بدل مؤقّتات الذاكرة** — كلّ عملٍ غير فوريّ مهمّةٌ في ريدِس لها إعادة محاولة.
2. **الأدوات معرَّفة بالبيانات لا بالكود** — وإلّا فكلّ عميلٍ جديد نشرٌ جديد.
3. **الأسرار مشفَّرة بمفتاحٍ رئيس** — وإلّا فأوّل نسخةٍ احتياطيّة مسرَّبة تكشف توكنات عملائك.

كلّ ما عداهما يمكن تحسينه تدريجيّاً.

## ٤.٢ الستاك المختار ولماذا

| الطبقة | الاختيار | لماذا هذا بالذات |
|-------|---------|-------------------|
| اللغة | **TypeScript** على Node 22 | تعرفها، والمحرّك الحالي بها؛ نقل المنطق مباشر |
| المستودع | **pnpm workspaces + Turborepo** | نواة البوت تُستعمل في الـAPI وفي العمّال وفي الاختبارات: حزمةٌ واحدة لا نسخ |
| الـAPI | **Fastify 5 + Zod** | أسرع من Express في استقبال الويبهوك، وتحقّقٌ من المخطّط مدمج، وhooks نظيفة لحقن المستأجر. (Express يعمل، لكنّك ستكتب يدويّاً ما يعطيه Fastify جاهزاً) |
| القاعدة | **PostgreSQL 16 + Drizzle** | تعرف Drizzle، والترحيلات في الكود شرطٌ لجاهزيّة الترحيل |
| الطوابير | **BullMQ على Redis 7** | تأخير (debounce)، أقفال، إعادة محاولة أسّيّة، حدّ معدّل لكلّ مستأجر، طابور موتى، لوحة مراقبة |
| اللحظيّ | **Socket.io** | تعرفه، وغرفةٌ لكلّ مستأجر `t:{id}` تحلّ العزل ببساطة |
| الواجهة | **Next.js 15 (App Router) + React 19** | تعرف Next؛ والـApp Router يعطي حدوداً واضحة بين خادم وعميل |
| التنسيق | **Tailwind v4 + shadcn/ui** | مكوّنات جاهزة يمكن تعريبها، ووقت بناء الواجهة هو ما سيلتهم جدولك |
| حالة الخادم | **TanStack Query** | إعادة الجلب والتزامن مع أحداث السوكِت بلا كود يدويّ |
| الإشعارات | **Web Push (VAPID) فقط** | تجربتك مع FCM+VAPID معاً أثبتت أنّ المسار المزدوج يضاعف الأعطال. PWA وحدها تكفي: أندرويد، iOS 16.4+ مثبَّتاً، سطح المكتب — بلا مشروع Firebase ولا `google-services.json` |
| الذكاء | **طبقة مزوّدين**: Gemini (افتراضيّ) · Claude · OpenAI | القياس أثبت $0.0024/ردّ مع Gemini؛ والعزل يجعل انقطاع مزوّدٍ خللاً لا كارثة |
| السجلّات | **pino** (JSON) + جدول `incidents` | السجلّ للتشخيص، والجدول للتنبيه والعرض |
| الاختبار | **Vitest** + بطّاريّة `e2e-*.ts` تُشغَّل على الخادم | نمطك المجرَّب: الاختبار على الخادم لا محلّيّاً |

### ما رُفض ولماذا

- **NestJS**: بنيةٌ ثقيلة لمشروع شخصٍ واحد؛ ستصرف أسبوعاً على المزخرِفات (decorators).
- **Prisma**: أبطأ في الترحيلات ولا يضيف على Drizzle هنا.
- **Supabase/Firebase مُدارة**: تناقض قرار الاستضافة، وتجعل بيانات عملائك خارج سيطرتك.
- **Kafka/RabbitMQ**: حجمك لا يبرّرهما؛ ريدِس موجودٌ أصلاً.
- **قاعدة بيانات لكلّ عميل**: ترحيلٌ في خمسين قاعدة عند كلّ تغيير مخطّط. مرفوض حتّى ٥٠ عميلاً.

## ٤.٣ شكل المستودع

```
aibot/
├─ apps/
│  ├─ api/          Fastify: مسارات، ويبهوك لكلّ مستأجر، سوكِت، مصادقة
│  ├─ worker/       عمّال BullMQ: الرسائل، الردود، المراقبة، الصيانة
│  └─ web/          Next.js: /console (المالك) و /app (العميل)
├─ packages/
│  ├─ db/           مخطّط Drizzle + الترحيلات + withTenant()
│  ├─ core/         ★ نواة البوت: حلقة الوكيل، الحرّاس، السياق، الأدوات
│  ├─ channels/     محوّل القناة: cloud-api (اليوم) — الواجهة تحتمل غيره
│  ├─ ai/           مزوّدو النماذج خلف واجهة واحدة + القياس والتسعير
│  ├─ crypto/       تشفير الأسرار (AES-256-GCM) والتقنيع
│  └─ shared/       أنواع Zod مشتركة بين الـAPI والواجهة
├─ docker-compose.yml · deploy.sh · .env.example
```

`packages/core` لا يستورد Fastify ولا Drizzle مباشرةً: يأخذ **منافذ** (ports) —
`loadContext`, `saveMessage`, `sendOut`, `callModel` — فتُختبر النواة بلا قاعدة بيانات،
تماماً كما تُختبر محرّكات اللعبة عندك بـ`__primeDefsForTest`.

## ٤.٤ تدفّق الرسالة الواردة (المعمارية الجديدة)

```
POST /api/webhooks/wa/:tenantPublicId
  │ ① جلب المستأجر بالمعرّف العامّ (كاش ريدِس ٦٠ ثانية)
  │ ② تحقّق التوقيع بـappSecret الخاصّ به — إلزاميّ، بلا استثناء
  │ ③ ردّ 200 فوراً
  │ ④ enqueue  wa:inbound  { tenantId, payload }
  ▼
عامل inbound
  ├─ لكلّ رسالة: dedupe بالـwamid (قيد فريد + فحص ريدِس)
  ├─ upsert جهة الاتّصال والمحادثة، تحديث lastInboundAt
  ├─ فتح/تمديد نافذة المحادثة (conversation_windows)
  ├─ كشف إلغاء الاشتراك · وسوم · بثّ حدث سوكِت للوحة العميل
  └─ enqueue  bot:reply  { conversationId }  بتأخير ٢٠٠٠ms ومفتاح jobId = conv:{id}
       ← التأخير + jobId الثابت = «دمج الرسائل المتتالية» بلا مؤقّت في الذاكرة:
         رسالةٌ جديدة تستبدل المهمّة المؤجَّلة نفسها
  ▼
عامل bot:reply   (تزامن محدود لكلّ مستأجر عبر مجموعة معدّل)
  ├─ قفل ريدِس lock:conv:{id} (ttl ٦٠ث) — لا ردّان متوازيان
  ├─ بوّابات: البوت مفعَّل؟ الاشتراك حيّ؟ السقف؟ ساعات العمل؟ الإيقاف البشريّ؟
  ├─ بناء السياق: الشخصيّة المنشورة + المعرفة + الحقائق الحيّة + بطاقة الزبون + التاريخ
  ├─ حلقة الوكيل: نموذج ⇄ أدوات (حتّى maxLoops)
  ├─ الحرّاس: تسريب الأدوات · طول الردّ · الروابط · السياسة
  ├─ enqueue  wa:outbound  { conversationId, payload }
  └─ كتابة usage (توكنز · كلفة · أدوات · أعلام · زمن)
  ▼
عامل outbound  (حدّ معدّل لكلّ مستأجر: افتراضيّاً ١٠/ث، وقابل للضبط)
  ├─ حارس النافذة: مغلقة ⟵ فشلٌ صريح، لا التفاف
  ├─ استدعاء Graph API بتوكن المستأجر (مفكوك التشفير في الذاكرة فقط)
  ├─ خطأ قابل للإصلاح (429/5xx) ⟵ إعادة محاولة أسّيّة ٥ مرّات
  ├─ خطأ دائم ⟵ حادثة + إشعارك + وسم المحادثة
  └─ تخزين الرسالة الصادرة + بثّ سوكِت
```

**لماذا هذا أفضل جوهريّاً من الحالي:** كلّ صندوقٍ أعلاه مستقلّ وله إعادة محاولة. إعادة تشغيل
الخادم في أيّ لحظةٍ تُستأنف من ريدِس. اليوم، إعادة تشغيلٍ أثناء debounce تعني ردّاً لم يُرسل
أبداً ولا أحد يعلم.

## ٤.٥ الطوابير وأسماؤها

| الطابور | المُنتِج | التزامن | السياسة |
|--------|---------|---------|---------|
| `wa:inbound` | الويبهوك | ١٠ | ٣ محاولات، DLQ |
| `bot:reply` | inbound | ٣ لكلّ مستأجر | تأخير ٢٠٠٠ms، jobId ثابت، محاولتان |
| `wa:outbound` | reply · الموظّف · النظام | حدّ معدّل لكلّ مستأجر | ٥ محاولات أسّيّة |
| `media:transcribe` | inbound (صوت) | ٢ | محاولتان |
| `kb:ingest` | رفع ملفّ | ١ | مرّة واحدة، تقدّم مرئيّ |
| `health:poll` | مجدوِل متكرّر | ٥ | كلّ ١٠ دقائق لكلّ مستأجر، موزَّعة زمنيّاً |
| `usage:rollup` | مجدوِل | ١ | كلّ ساعة: تجميع الاستهلاك وتقييم السقوف |
| `notify:push` | أيّ مصدر | ٥ | تجميع وكبح (`09`) |
| `maintenance:*` | مجدوِل | ١ | إغلاق النوافذ، الأرشفة، النسخ |

## ٤.٦ ما يبقى خارج الطوابير عمداً

ردّ الويبهوك (يجب أن يكون فوريّاً)، قراءات الواجهة، وبثّ السوكِت. كلّ ما عدا ذلك — وخصوصاً
كلّ نداءٍ خارجيّ (ميتا، النموذج، أدوات HTTP للعميل) — يمرّ بطابور.

## ٤.٧ مخطّط الاعتماديّات (لا دوائر)

```
web ─→ api ─→ core ─→ {ai, channels, crypto}
                │
worker ─────────┘       الكلّ ─→ db, shared
```

قاعدة: `core` لا تعرف HTTP ولا Fastify ولا Socket.io. إن احتاجت شيئاً فهو منفذٌ يُحقَن.
