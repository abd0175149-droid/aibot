# مراقبٌ خارج المضيف — الشيء الوحيد الذي يخبرك أنّ الخادم كلَّه سقط

> خمس دقائق من العمل مرّةً واحدة. وبدونه، كلُّ ما بُني من مراقبةٍ يموت مع
> ما يراقبه.

## المشكلة بالضبط

كلُّ ما في `apps/worker/src/health.ts` و`incidents.ts` و`notify.ts` يعمل **على
المضيف نفسه**. فانقطاع الكهرباء، أو سقوط `dockerd`، أو موت نفق Cloudflare،
يُسقط الـAPI والعاملَ والمُنبِّهَ معاً. الحادثة تُكتب في قاعدةٍ لا تعمل، وتُدفع
من عاملٍ لا يعمل، والمالك نائمٌ لا يعلم — وهو بالضبط حادث ٢٠ أيلول الذي أُنشئ
نظامُ المراقبة لتفاديه، معاداً على مستوى المضيف.

ولا يُصلَح هذا بشيءٍ في هذا المستودع: **مراقبٌ داخل الخادم لا يبلّغ عن موته.**

## ما أصبح متاحاً في الشيفرة (وهو نصف الحلّ)

`GET https://aibot.masaros.net/api/health` يردّ الآن:

```json
{"service":"aibot","rev":"…","db":true,"redis":true,"worker":true,"workerAgeSec":7}
```

* `worker` نبضةٌ يكتبها العامل في ريدِس كلّ ١٥ ثانية بعمر ٤٥ ثانية.
  **غيابها هو الخبر**: عاملٌ سقط أو عَلِق أو قُتل يُقرأ `worker: false` بلا أن
  يُسأل أحد. وهذا أوّل مرّةٍ يُرى فيها حال العامل من **خارج** المضيف.
* `db` و`redis` كما كانا، والحالة `503` إن سقط أحدهما.

## النصف الآخر — يُضبَط مرّةً بيدك

أيّ خدمة مجّانيّة تكفي (UptimeRobot · BetterStack · Healthchecks.io). المهمّ
ثلاثة شروط، وكلٌّ منها وُلد من عطلٍ وقع:

### ① طابِق **الجسم** لا كود الحالة

`*.masaros.net` جامعٌ يوجّه أيّ اسمٍ غير معرَّف إلى تطبيقٍ آخر يردّ `200`.
فمراقبٌ يفحص الكود وحده يبقى أخضرَ بينما AiBot ساقطٌ تماماً.

```
URL:            https://aibot.masaros.net/api/health
Keyword:        "service":"aibot"
Type:           Keyword — alert when keyword NOT present
Interval:       5 minutes
```

### ② طابِق نبضة العامل أيضاً

فحصٌ ثانٍ على نفس العنوان بكلمةٍ مفتاحيّةٍ أخرى — فسقوط العامل وحده لا يغيّر
كود الحالة ولا يُسقط الـAPI:

```
Keyword:        "worker":true
Type:           Keyword — alert when keyword NOT present
```

### ③ اجعل قناة التنبيه خارج المضيف

بريدٌ أو رسالةٌ نصّيّة أو تطبيق المراقب نفسه على هاتفك. **لا** ويبهوك يمرّ
بـ`aibot.masaros.net`: قناةُ تنبيهٍ تمرّ بالنظام الذي تراقبه ليست قناةَ تنبيه.
(الدرسُ مدفوعٌ مرّتين: مرّةً حين ماتت التنبيهات مع الحظر لأنّها كانت عبر
واتساب، ومرّةً حين كانت الحوادث تُكتب ولا تصل أحداً لأنّ لا مشترك.)

## كيف تتأكّد أنّه يعمل — لا تفترض

```bash
# ① الجسم يحمل ما يطابقه المراقب
curl -s https://aibot.masaros.net/api/health

# ② أوقف العامل وحده، ثمّ اقرأ خلال دقيقة
ssh mafia-prod 'cd ~/aibot && docker compose stop worker'
sleep 50 && curl -s https://aibot.masaros.net/api/health   # يجب أن يقول worker:false
ssh mafia-prod 'cd ~/aibot && docker compose start worker'

# ③ انتظر تنبيه المراقب فعلاً. تنبيهٌ لم يصل ليس تنبيهاً.
```

الخطوة ② هي الاختبار الحقيقيّ: إن لم يتبدّل `worker` إلى `false` فالنبضة
معطوبة، وإن تبدّل ولم يصلك شيءٌ فالمراقب ليس مضبوطاً.

## ما لا يغطّيه هذا

سقوط الشبكة المنزليّة كلّها يمنع المراقب من الوصول — وهذا **مقصود**: عجزُه عن
الوصول هو نفسه الإنذار. أمّا القرص الممتلئ الذي يُبقي الـAPI حيّاً ويُسقط
الكتابة، فيظهر في `db:false` عند أوّل استعلامٍ يفشل.
